# Apple Design workspace refinement · 2026-11-01

Based on upstream `da40fe5a3aba9632cce1939631431e80d37b29c3`.

`workspace-design.css` provides one presentation layer for CRM, BD Publishing,
Marketing Publishing and account entry. It improves small-text legibility,
table spacing, cards, semantic color, focus indicators, mobile forms and
reduced-motion/transparency/contrast preferences. The overview presents the
four business lines together on wide screens and moves tasks/activity below.

`workspace-ui.js` docks the existing account bar inside the header, adds
Publishing navigation icons, and provides a mobile More button that invokes
the existing workspace menu. It animates native Publishing dialogs with a
critically damped spring, without delaying closure or locking input. Existing
CRM drawer animation and keyboard/focus handling stay in `apple-ui.js`.

The existing IDs, actions, fields, business calculations, data migration,
Supabase adapters, auth gate and server policies are preserved. The additional
login context contains branding only. No credentials or data are added to
production state.

Validation: the complete existing Node test suite passed before and after the
HTML changes: 421/421. All inline scripts and `workspace-ui.js` parse. Visual
and interaction QA uses `tests/visual/` generated by
`python tools/build-ui-preview.py` from the real application markup. Those
pages explicitly identify synthetic data, omit every Supabase/CDN script,
disable connections and form navigation through CSP, and replace Storage with
per-page in-memory fixtures. The normal application never loads the fixtures.
They do not verify a real authenticated production session.
